### 关系型数据库

- **关系型数据库是指采用了关系模型来组织数据的数据库。关系模型就是二维表格模型。**

#### 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **表(Table)** | 数据以行（记录）和列（字段）组成的二维表格存储 |
| **主键(Primary Key)** | 唯一标识每条记录的字段，不可重复、不可为空 |
| **外键(Foreign Key)** | 关联另一张表的主键，建立表与表之间的关系 |
| **索引(Index)** | 类似书的目录，加速数据查询，但占用额外存储空间 |
| **视图(View)** | 虚拟表，基于SQL查询定义，简化复杂查询、提高安全性 |
| **事务(Transaction)** | 一组操作要么全部成功，要么全部回滚，保证数据一致性 |

#### 优点

1. **二维表格，直观易懂**
2. **标准SQL语言，通用性强**
3. **支持事务ACID，数据一致性有保障**
4. **支持复杂查询（JOIN、聚合、子查询）**
5. **数据冗余低，易于维护**

#### 缺点

1. **高并发读写性能有限**（相比NoSQL）
2. **横向扩展困难**（不像Web服务器可以简单加机器）
3. **Schema固定**（表结构变更成本高）
4. **大数据量下查询性能下降**

#### 典型应用场景

| 场景 | 推荐数据库 | 原因 |
| :--- | :--------- | :--- |
| Web应用后端 | MySQL / PostgreSQL | 开源免费、生态成熟、社区活跃 |
| 金融/银行系统 | Oracle | 事务安全、性能稳定、企业级支持 |
| 微软技术栈 | SQL Server | 与.NET/Windows深度集成 |
| 移动端/嵌入式 | SQLite | 无需服务器、体积小、零配置 |
| 地理信息系统 | PostgreSQL + PostGIS | 强大的空间数据查询能力 |

### 非关系型数据库（NoSQL）

- **主要指那些非关系型的、分布式的，且一般不保证ACID的数据存储系统**

#### 分类

| 类型 | 代表 | 数据模型 | 适用场景 |
| :--- | :--- | :------- | :------- |
| **键值存储** | Redis, Memcached | Key → Value | 缓存、会话管理、排行榜、消息队列 |
| **文档存储** | MongoDB, CouchDB | JSON/BSON文档 | 内容管理、日志系统、大数据、灵活Schema |
| **列族存储** | Cassandra, HBase | 列族（Column Family） | 海量数据写入、时序数据、物联网 |
| **图数据库** | Neo4j, JanusGraph | 节点 + 边 | 社交网络、推荐系统、知识图谱 |
| **搜索引擎** | Elasticsearch, Solr | 倒排索引 | 全文搜索、日志分析、实时检索 |

#### 优点

1. **高并发读写性能强**（尤其内存数据库如Redis）
2. **横向扩展容易**（分布式架构，加机器即可扩容）
3. **灵活的数据模型**（无需预定义Schema）
4. **大数据场景下性能优异**

#### 缺点

1. **不支持复杂查询**（无标准SQL、JOIN困难）
2. **事务支持弱**（大多不支持完整ACID）
3. **数据一致性保障较弱**
4. **学习成本**（每种NoSQL有独立的查询语言/API）

### ACID 特性

> ACID是关系型数据库事务的四个核心特性

| 特性 | 英文 | 说明 |
| :--: | :--: | :--- |
| **A** | **Atomicity（原子性）** | 事务中的操作要么全部完成，要么全部不完成（失败回滚） |
| **C** | **Consistency（一致性）** | 事务执行前后，数据库从一个一致状态转变为另一个一致状态 |
| **I** | **Isolation（隔离性）** | 并发事务之间互不干扰，一个事务的中间状态对其他事务不可见 |
| **D** | **Durability（持久性）** | 事务一旦提交，对数据的修改就是永久的，即使系统故障也不会丢失 |

### 索引

| 概念 | 说明 |
| :--- | :--- |
| **作用** | 加速数据查询，类似书的目录。没有索引时数据库需要全表扫描 |
| **类型** | 普通索引、唯一索引（UNIQUE）、主键索引（PRIMARY）、全文索引（FULLTEXT）、组合索引 |
| **优点** | 大幅提升查询速度、加速排序和分组操作 |
| **缺点** | 占用额外磁盘空间、降低写入速度（每次INSERT/UPDATE需更新索引） |
| **原则** | 在WHERE、JOIN、ORDER BY 频繁使用的列上建索引；避免在低区分度的列（如性别）上建索引 |

### 事务

| 概念 | 说明 |
| :--- | ---- |
| **定义** | 一组数据库操作作为一个整体执行，要么全部成功，要么全部失败回滚 |
| **开始** | `BEGIN` 或 `START TRANSACTION` |
| **提交** | `COMMIT` — 确认所有操作生效 |
| **回滚** | `ROLLBACK` — 撤销所有未提交的操作 |
| **隔离级别** | 读未提交 < 读已提交 < 可重复读 < 串行化（隔离性越高，并发性能越低） |

### 备份与恢复

| 备份类型 | 说明 | 适用场景 |
| :------- | :--- | :------- |
| **全量备份** | 备份整个数据库，恢复最简单 | 数据量小、定期完整备份 |
| **增量备份** | 只备份自上次备份以来的变化 | 数据量大、减少备份时间和存储 |
| **差异备份** | 备份自上次全量备份以来的变化 | 恢复速度介于全量和增量之间 |
| **逻辑备份** | 导出为SQL语句（如 `mysqldump`） | 跨版本迁移、小数据量 |
| **物理备份** | 直接复制数据文件 | 大数据量、快速恢复 |

> **建议**：生产环境至少配置每日全量备份 + 实时binlog增量备份，并定期演练恢复流程

### 数据库选型建议

| 需求 | 推荐方案 | 理由 |
| :--- | :------- | :--- |
| **中小型Web应用** | MySQL | 免费开源、教程丰富、社区活跃 |
| **复杂查询/数据分析** | PostgreSQL | 功能强大、支持JSON/GIS、SQL标准兼容好 |
| **高并发缓存** | Redis | 内存读写极快、支持丰富数据结构 |
| **海量文档/灵活Schema** | MongoDB | 文档模型灵活、水平扩展容易 |
| **全文搜索** | Elasticsearch | 搜索性能优异、支持复杂分析查询 |
| **社交/推荐系统** | Neo4j | 图查询效率高、关系建模直观 |
| **嵌入式/本地存储** | SQLite | 无需服务器、单文件、零配置 |
| **大型企业系统** | Oracle / SQL Server | 企业级支持、高可用、完善的管理工具 |
